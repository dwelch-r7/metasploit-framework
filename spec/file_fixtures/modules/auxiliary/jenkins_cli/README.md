# Jenkins CLI wire fixtures

`responses.json` contains actual HTTP download bodies from official, digest-pinned
Jenkins 2.441/2.442 and LTS 2.426.2/2.426.3 controllers. The isolated lab lives in
`test/module_targets/jenkins/`. Its separate native CLI client has none of the
controller fixture files. The source revision, original body filenames, hashes,
file paths, padding state and decoded frame annotations accompany the raw bytes.
These public fixture files contain no operational Jenkins secrets.

The captures were taken at source revision
`e16b4bc4157b6ba385ccb4775362a2e043c56ae8`, diagnostic run
`20261109T134549-c734ea/jenkins_cli_diagnostic`. A private acceptance-spec wrapper
records the unchanged `@content_body` after `download_request` returns and before
`process_result` sees it. It does not alter requests, responses or return values.
For reproduction, use the lab's isolated console and prepend this recorder to
the loaded module class before running the module against the owned targets:

```ruby
klass = framework.modules.create('auxiliary/gather/jenkins_cli_ampersand_arbitrary_file_read').class
klass.prepend(Module.new do
  define_method(:download_request) do |uuid|
    result = super(uuid)
    @capture_number = (@capture_number || 0) + 1
    folder = File.join(Msf::Config.config_directory, 'cli-captures')
    FileUtils.mkdir_p(folder)
    File.binwrite(File.join(folder, "#{uuid}-#{@capture_number}.bin"), @content_body) if @content_body
    result
  end
end)
```

The HTTP transport first writes a zero readiness byte; the CLI frames then use a
four-byte signed nonnegative payload length, one-byte opcode and payload. STDERR
frames use opcode 8; EXIT uses opcode 4 with a four-byte exit status. See the
owning [HTTP transport](https://github.com/jenkinsci/jenkins/blob/jenkins-2.441/core/src/main/java/jenkins/util/FullDuplexHttpService.java)
and [CLI protocol source](https://github.com/jenkinsci/jenkins/blob/jenkins-2.441/cli/src/main/java/hudson/cli/PlainCLIProtocol.java).

`java_reference.json` is distinct from the network captures. It records bytes
generated by the included `UtfReference.java` using genuine JDK
`DataOutputStream.writeUTF`/`writeInt`, including long, Unicode, null,
supplementary-character, alternate-encoding-name and field-limit boundaries.
Reproduce from this directory with the recorded image:

```sh
docker run --rm --network none --mount "type=bind,src=$PWD/UtfReference.java,dst=/tmp/UtfReference.java,readonly" \
  --entrypoint java \
  jenkins/jenkins:2.442-jdk17@sha256:c80c93820944076423853cfd833d83c2bbd6e2000506eb4ff193b577edf8b017 \
  /tmp/UtfReference.java
```

Fragmented, malformed, stdout-only, whitespace and exit-status variants in the
spec are explicitly derived from the captured bytes. They are unit boundaries,
not claims of extra live target/protocol qualification.
