## Vulnerable Application

Ni8mare, CVE-2026-21858, is a content-type confusion flaw that permits file access through
certain form-based n8n workflows. The [vendor advisory](https://github.com/n8n-io/n8n/security/advisories/GHSA-v4pr-fm98-w9pg)
identifies versions 1.65.0 up to, but excluding, 1.121.0 as affected and 1.121.0 as fixed.

This module authenticates with `USERNAME` and `PASSWORD`, creates a temporary file upload
workflow, and uses it to read the selected file. It requires an account allowed to create
and execute that workflow. It does not implement the deployment-specific prerequisites for
unauthenticated file extraction described in the
[Ni8mare analysis](https://horizon3.ai/attack-research/attack-blogs/the-ni8mare-test-n8n-rce-under-the-microscope-cve-2026-21858/).

The `READ_FILE` action saves the extracted bytes as loot. `EXTRACT_SESSION` reads n8n's SQLite
database and configuration, selects the row matching `TARGET_EMAIL`, and derives a JWT for
that user. A selected user's ticket does not grant a role beyond that account's permissions.
Printing a ticket does not verify that the target accepts it, and this module does not create
an operating system session.

The user-hash claim follows n8n AuthService's standard Base64 contract, including `+` and `/`
characters. The JWT header, payload and signature retain Base64url encoding. The signing-key
derivation uses the default secret derived from the configuration's `encryptionKey`.
Custom JWT signing secrets and MFA-specific claim inputs are not handled by this action.
Disabled accounts and other server-side session restrictions may prevent token acceptance.

Extracted password hashes are reported as nonreplayable hashes with their detected format
and an import origin referencing the saved database loot. They are not reported as validated
plaintext passwords or successful logins. SQLite handles are closed after selecting the user,
including when the query or a later extraction fails.

### Installation

For a controlled local 1.120.0 lab, run:

```sh
docker run --rm --init --name n8n-ni8mare \
  --cpus 1 --memory 1536m --pids-limit 256 \
  -p 127.0.0.1:5678:5678 -e N8N_SECURE_COOKIE=false \
  n8nio/n8n:1.120.0
```

Complete n8n's initial account setup and configure the account used for workflow creation.
The cookie setting above is for this localhost HTTP lab. Select a known lab account for
`TARGET_EMAIL`; retain its actual database role when verifying the resulting ticket.

## Verification Steps

1. Install the affected lab application and prepare the workflow-creation credentials.
2. Start msfconsole and select `auxiliary/gather/ni8mare_cve_2026_21858`.
3. Set `RHOSTS`, `RPORT` (5678 for the lab), `USERNAME` and `PASSWORD`.
4. Set `ACTION READ_FILE` and `TARGET_FILENAME` to a controlled file, then run the module.
   Compare the saved loot with the exact file bytes, including binary content where applicable.
5. Set `ACTION EXTRACT_SESSION` and `TARGET_EMAIL` to a known account, then run the module.
   Expect saved database/config loot, the extracted user ID/hash and a JWT ticket.
6. With a Framework database enabled, confirm the extracted hash is recorded as a
   nonreplayable hash with its format and database-file origin, rather than a plaintext password.
7. Independently present the ticket to the target and verify the authenticated user ID and role.
   A printed ticket or an HTTP success alone does not establish the selected identity.
8. Confirm the temporary workflows are archived and deleted. Follow any manual-cleanup warnings.

The historical Scenarios below retain earlier option labels. Use the current names above
and in the Options section when configuring the module.

## Options

### USERNAME

Email address of the account used to create and execute the temporary file upload workflow.

### PASSWORD

Password for `USERNAME`.

### TARGET_EMAIL

For `EXTRACT_SESSION`, the email address of the user whose database row supplies the JWT identity
and hash. The action does not automatically select an administrator.

### TARGET_FILENAME

For `READ_FILE`, the absolute path of the file to extract.

### N8N_CONFIG_DIR

For `EXTRACT_SESSION`, the absolute n8n configuration directory, normally `/home/node/.n8n/`.
The action reads `database.sqlite` and `config` from this directory.
