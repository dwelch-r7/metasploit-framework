# RocketMQ execution verification — 11 November 2026

The checkpoint is **198 qualified modules, 144 profiles and 1,561
passing functional examples**. The [session lab](rocketmq_sessions/README.md) and
[command lab](rocketmq_commands/README.md) qualify the main execution paths of
`exploit/multi/http/apache_rocketmq_update_config`. The earlier
[discovery qualification](VERIFICATION-20261111-rocketmq.md) remains valid after
replay. The broad module campaign remains incomplete.

## Genuine targets and bounded runs

The original Apache RocketMQ 4.9.4 and 5.1.1 NameServer/Broker main classes run
from the pinned vendor images described in the discovery report. Actual runtime
image layer prefixes match both SHA256-verified manifest/config chains. No server
request handler is patched. Brokers advertise port **10921**, so the exploit
must discover the real endpoint instead of relying on 10911.

Native SDK controls verify versions, route, Broker PID, UID3000, configuration
reads and same-value updates before module calls. A fresh SDK-injected command
must execute on 4.9.4 and remain absent on 5.1.1 throughout a 36-second window;
the SDK restores its changes and removes its marker. Full final native snapshots
must retain configuration, route and PID.

An ordinary Framework handler independently generates each real Bash and default
staged fetched Meterpreter payload using the exploit's actual bad-character
constraint. Its already generated bytes are streamed to a UID3000 script,
SHA256-checked and executed directly. Both native sessions require actual remote
file, process and kernel socket proof, graceful exit, and complete local/remote
cleanup before owning execution. No owning method or payload encoder is stubbed.
The generic command has a separate normal Framework generation/native execution
control with a fresh marker.

Profiles run sequentially. Discovery uses **three containers, 2,048 MiB/1.5 CPUs**.
Sessions, fixed-target refusal and commands each use **two containers,
1,408 MiB/1.25 CPUs**.
Framework has 768 MiB/one CPU; each target has 640 MiB/0.25 CPU. All have 256-PID
limits, swap equal to RAM, no privileged mode, and one project bridge. Only
random loopback NameServer ports are published. First consoles have real fresh
metadata and no manual seed; later profiles in the same invocation use verified
normal metadata reuse.

## Confirmed defects and separate fixture failures

Real native Bash and Meterpreter calibrations passed before the original module
was blamed. The old owning Bash requests failed to open sessions because Java
`Properties.load(InputStream)` consumed payload backslashes. The fix escapes
properties backslashes/newlines, uses UTF-16 Unicode escapes for that Java API,
and frames byte counts. The identical carrier suite has **7 failures before and
zero after in 18 examples**; the bounded Java oracle passes 7/7. The 34-file fix
package manifest is
`dfa718c56c75198a8ddcfd90531bda31da4f2ee8edd6975aea3f6bf07984e542`.

The original module did open a genuine owning Meterpreter session, but its
callback left Home with a trailing semicolon and filterServerNums at 1 instead
of 0. It also skipped base callback bookkeeping. The fix snapshots exact values
before modifying them, restores/verifies against the original endpoint on a real
callback, and retries failed callback cleanup. Bounded reads handle fragmented
configuration frames. No-callback commands remain pending for operator recovery;
a handler timeout is never treated as execution proof. The eight original
cleanup regressions all fail before the fix; the worker's final focused suite
passes 75/0 and root's related suite passes **104/0**. The 84-file fix manifest is
`7ea1dd9fa72ebd2b6886742f1b7d8673ae0ec2b71528c35b67619cdac1997989`.

The original module-failure run `20261111T135300-d39949` retains its actual
calibrations, failed Bash calls, real Meterpreter proof and two-value config
difference. Its 138-file package manifest is
`7f8119ec1c16efe7c87f147106373c5e7b4bc7257d403fcba3964a4eafc453ae`.
An earlier native-shell fixture failure waited for FIN_WAIT2 before closing the
host shell handle; its correction and separate 203-file evidence are preserved,
manifest `1017b8be2aee239671b9132c8093abd6bc3a34713335f7a31984f520e2fc993c`.

The first fixed-module session replay records four passing RSpec cases and all
six successful owning lifecycles, but the manager's 600-second bound interrupts
the final fixed-target native snapshot. It remains **unqualified** as a complete
profile. A cold-console replay also hits the same bound after five complete owning

`7cd5de3981b612986fa919c9cf4a9c952a677e95c294e72a5ac522947b706db1`.
Removing duplicate successful cleanup checks alone did not provide enough

These are fixture timing corrections, not further production-module defects.

## Review and limits

**Summary:** Genuine SDK/payload controls, repeated public module calls, exact
state/lifecycle proof and independent teardown qualify the main tested paths.

**What looks good:** Failed setup, failed module behavior and operator recovery
are retained separately. Source-current input hashes and actual terminal results
agree; existing human Scenarios are preserved.

**Concerns:** No new concern remains within this scope. The existing default
PAYLOAD lint warning remains; module msftidy exits 2 for that same warning.
Changed helpers/specs have no new offenses; module documentation passes its
checker. Runtime coverage is limited to these two releases, IPv4, JSON frames,
ACL-disabled services, Bash, generic commands and staged fetched Linux
Meterpreter. Other releases/fix branches, ACL plugins/authentication, IPv6,
binary serialization and other delivery families remain unqualified. A callback
cannot observe non-session command completion; operator recovery is explicit.

**Suggestions:** Continue the remaining valuable target queue. Current static
inventory has **200 registered sources, 305 pending documented hints, sixteen
individual reviews and zero stale reviews**. Registration is not qualification.
The older discovery report's derived-image IDs and pending-hint count were
corrected against its saved final-run identities and historical manifests.
No PR is created.
