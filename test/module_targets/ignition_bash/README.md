# Ignition default Bash sessions

Run with Framework's bundle and Docker Compose v2:

```sh
MODULE_TARGET_NAMESPACE=ignition-bash-local bundle exec ruby tools/dev/run_guarded_module_target_tests.rb ignition_bash
```

This profile extends the pinned, unmodified application in `../ignition`.
A genuine installed-class PHAR/HTTP command control first proves UID 33 execution.
The native callback, exact stock Bash payload and native handler run as
`www-data`, matching the real Apache worker identity. An independent native
session gates the owner's default Bash session and explicit repeated execution.
The first owner attempt omits both TARGET and PAYLOAD; the repeat uses the same
selected console object with AutoCheck disabled.

Each session must create exact physical proof bytes, expose the expected new
PID/birth identity and established socket, and own an open reporting row.
Public shell APIs request shutdown; checks require process/socket disappearance,
the original database row's closure and the full baseline process set's return.
The synchronous gadget resumes after shell shutdown and the installed LazyOption
raises its observed return-type exception. Read-only checks require that one
expected UID-33 log entry. It stays in place before the repeated owner execution;
no native control clears or repairs it between the two attempts. The resolved
target index is checked separately because an unset TARGET datastore value is a
valid selection of the normal default.

A read-only Apache prefork configuration keeps four real workers available and
stable while an HTTP request holds the shell open. No application/vendor source
or payload implementation is patched. Before/after source hashes and cgroup
events bracket the profile. The application is capped at 1 CPU, 512 MiB/equal
swap and 128 PIDs; the disposable reporting database adds 0.2 CPU, 128 MiB/equal
swap and 64 PIDs. HTTP and database ports bind only to loopback.

Run one stack at a time through the guarded runner. Its task namespace, shared
heavy lock and ensure cleanup remove both containers, the ephemeral network and
reporting data after success, failure or interruption. Never retain a finished
stack. A failed native control withholds the owner verdict. Other releases,
Windows, patched packages and broader pre-existing-log states need separate
qualification.
