# Lucee native-gated command owners

Two new profiles qualify **4/0 each**, with **eight actual owner commands**.
Eight existing profiles retain **31/0** after current-input and raw-proof
audits. The latest ten-profile set therefore has **39 qualified cases** and
**thirteen retained sessions used and closed**; there are no new session runs
in this tranche. Two owners, two profiles and eight historical cases bring the
campaign to **321 runtime owners, 680 qualified profiles and 4,814 historical
functional cases**. The broader inventory remains incomplete. No PR is created.

The image-write profile's accepted 4/0 comes from a mixed frame that also has
four scheduled-profile setup failures. That whole frame remains failed. The
image profile's own declared inputs and proofs remain current; only the
unselected scheduled helper changes afterward. The final scheduled-only run
passes 4/0. This report does not describe an aggregate 8/0 execution frame.

## Genuine shared target and native prerequisites

Both recipes use the official Linux amd64 **Lucee 5.3.7.43** image at digest
`sha256:2c4c766b5382e3969bc603803629ad28f5c6c26efc93e59b0be514b3c4aa498c`.
An isolated filesystem inspection verifies the actual Tomcat connector is
**8888**, despite image exposure metadata listing 8080. Runtime probes establish
Java **11.0.8**, UID **0**, webroot `/var/www/` and the real Lucee context and
temporary directories. Vendor JAR SHA256 is stable before and after:
`0a17b6c6c647959eabcb96245b4fb6ab3d5dc0a86462b55d83510f0f18aa7932`.

The inspected JAR's nested admin archive contains the genuine `imgProcess.cfm`,
login and scheduling templates. No vendor code, authentication implementation
or HTTP transport is patched. A separately mounted application template calls
normal CFML APIs for independent controls. Actual owner traces must show the
vendor/admin and uploaded CFML routes, never that native helper route.

The successful native-only pilot proves four command byte families, physical
image-write delivery and real interpretation through the `/lucee/` mapping.
Normal CFAdmin configuration sets a lab web password; an independent valid HTTP
login succeeds and a wrong login is denied. A genuine scheduler then downloads
CFML from a host HTTP source, publishes exact physical bytes, executes it through
Tomcat and deletes the task and file. Both observed source requests include
`RequestTimeout=10`. Final native metadata and JAR hash match the initial state,
all tasks are absent and the stack is removed before owner qualification.

The vendor lists fixes in 5.3.5.96, 5.3.6.68 and 5.3.7.47 in its
[CVE-2021-21307 advisory](https://github.com/lucee/Lucee/security/advisories/GHSA-2xvv-723c-8p7r).
A 5.3.7.47 image digest is resolved for future work; **no fixed-release runtime
is qualified here**.

## Actual image-write owner

The [image-write profile](lucee/README.md) tests the real reason-bearing
**Appears** check, then Unix TARGET 0 with `cmd/unix/generic`. Independent Bash
and real CFML execution establish exact command bytes before each attempt.
ASCII and combined quotes, backslashes, dollar/metacharacter text, Unicode,
CRLF, LF and tab content each execute twice on the same selected console object.
AutoCheck runs first and is disabled for the repeat.

All four actual owner commands create exactly one copy of the expected physical
file bytes as UID 0. Traces bind the encoded command to the genuine uploaded
CFML request. Each uploaded source file is independently read and compared to
the actual module-generated bytes **plus the real writer's trailing LF**.
The direct check invokes the missing-form-field probe without writing a stub.

## Actual authenticated scheduled owner

The [scheduled profile](lucee_scheduled/README.md) first calibrates valid HTTP
login and genuine scheduler publication. WEBrick, already in the locked project
dependencies, serves a standalone native source and handles the scheduler's
query parameter through its normal HTTP routing. An explicitly selected IPv4
Docker-host route is proved before owner execution.

The actual Unix TARGET 1 uses the lab admin password and `cmd/unix/generic`.
ASCII and the combined byte case each repeat on the same selected object. Four
actual commands create exact UID-0 bytes. For each, the actual downloaded CFML
matches a traced `cfm_stub` return; its embedded Base64 command decodes to the
expected bytes. The real admin UI path creates, updates and runs the task.
Native observations then verify that **the module itself deleted the task**
and that its host payload listener closed before fixture file cleanup occurs.

A final actual wrong-password attempt returns the module's NoAccess message,
without creating a task or reaching its CFML source producer. Native tasks stay
empty and the payload listener remains closed. This case runs last because a
bad login briefly delays subsequent authentication on this real release.

Both profiles explicitly set the normal **`AllowNoCleanup=true`** option for
sessionless commands. Their fixture cleanup removes recorded command proofs,
uploaded/downloaded CFML and the image-write temporary directory, verifying
absence before reuse. This is **fixture cleanup**, not proof of automatic
FileDropper session cleanup. That session path and normal default payload
selection remain separate qualification work.
