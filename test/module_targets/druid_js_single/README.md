# Single-version Druid JavaScript validation

These NEW profiles are a resource-constrained continuation of the immutable
Druid checkpoint. They have not run natively or through Framework yet. Existing
JNDI14/session5 evidence and all original failures remain unchanged.

After an explicit serial runtime grant, select the affected14 and fixed1
profiles in one canonical invocation. Each uses exactly five services: genuine
PostgreSQL, ZooKeeper, one official Druid release, Apache and Framework. Pins
remain 0.20.0 versus fixed0.20.1; one release is never aliased as both targets.
The existing runner/SDK and its120/120/600-second bounds are unchanged.

Configured ceilings are2208MiB and2.35 logical CPUs in total, not measured
requirements. Container ceilings exclude Docker VM and host RSpec overhead.
Native startup, actual resource limits/JVM options, healthy
leadership/metadata, three actual rows, real authentication/denial, exact
execution/refusal markers and no OOM must pass before module qualification.
The low-memory PG-only extension topology itself remains unqualified until
those gates run. No wire/compiler/LDAP sidecar or new project dependency.

All original fifteen case labels and two iterations remain: affected14 has
three positive checks, five auth/path/unrelated negatives, five command forms
and quiet output; fixed1 has the genuine patched negative. Exact executing
CMD/execute_command input, native same-command bytes/removal before Framework,
fresh target UID/GID1000 bytes, strict copies and state/listener restoration
are required. Public target/payload compatibility is retained. This profile
adds no session claims and changes no existing session assertions.

The existing Rex HTTP subscriber fires BEFORE send/transform; it alone is not
wire evidence. A selected-client-only passive observer delegates that subscriber
and the real socket put call once. It records pre-send data separately from
the actual already-serialized SOCKET-WRITE argument, full returned byte count,
real peer and genuine reply. Parse complete actual writer bytes, compare the
JSON command and pre-send body, then require independent real target bytes.
No payload regeneration or extra request serialization is used. It is labelled
SOCKET-WRITE, not PCAP or receiver-side packet capture. Native urllib producers
remain independent; a real ordinary-row Rex calibration must also pass.

Focused local observer specs cover original return/error preservation, exact
argument/delegation counts, no extra serialization, short writes, audit failures,
per-instance scope and challenge attempts. They establish code contracts only;
they are not native client/target or resource feasibility proof. HTTP Basic and
plain IPv4 only; no NTLM/Kerberos/proxy/evasion/TLS claims. Sampling remains at
least once. Original human module Scenarios remain untouched.
