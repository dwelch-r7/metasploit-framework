The unchanged pinned r1605-ls199 target and MariaDB extend the command profile.
A third 128 MiB / 0.2 CPU PostgreSQL service records real Framework sessions.
The application remains capped at 384 MiB / 0.7 CPU and MariaDB at 256 MiB /
0.3 CPU, with equal swap caps. Run one profile at a time; the guarded runner
namespaces and removes every service and ephemeral network on all exits.

Native installation, source fingerprints, PHP proof and contained loopback mail
settings precede a UID1000 callback round trip. The stock staged PHP Meterpreter
must work through both CLI execution and genuine registration/multipart upload.
Both sessions are used for exact physical file proof and closed before the owner
runs. Native fixture account/options recovery is explicit.

The unmodified owner then runs twice, preserving default target/payload selection,
with AutoCheck enabled and disabled on one selection. Original payload and HTTP
observations, exact UID/bytes, PID/birth, callback socket inode, original session
report closure, portal rows and physical upload inventories are recorded. PHP-FPM
may reuse its workers after a request; worker ancestry and socket closure are
checked rather than requiring every session PID to disappear. CLI processes must
exit. UID proof comes from the file owner; the stock optional POSIX extension is
not installed to influence Meterpreter's best-effort getuid output.

The full option-preservation assertion remains strict and separate from session
success. The command profile already records a six-option preservation defect
and remaining created clients. Actual state is retained before deliberate fixture
recovery. This profile's registration does not assert that it passes; consult the
dated report and raw results. Other payload families/releases remain separate work.
