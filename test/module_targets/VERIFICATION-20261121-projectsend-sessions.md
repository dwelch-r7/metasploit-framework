## Proven payload stream-framing defect

The installed **metasploit-payloads 2.0.257** passes its complete manifest
integrity check. The actual decrypted `meterpreter.php` SHA256 is
`e031bea39090ccc1c3086474c971c00368006e9105aa198d783f94225b36740d`.
The [standalone probe](projectsend_sessions/fragment_probe.php) loads the original
function definitions without replacing `read`, `dispatch_tcp` or protocol helpers.

On a genuine loopback TCP connection, a complete **72-byte** shutdown packet is
processed and returns `DISPATCH_EXIT`. Sending only its initial **32-byte** header
causes immediate `DISPATCH_RETIRE`, closes the server resource and never processes
shutdown, although the client has not closed the connection. The same original
reader returns an empty string on an open stream with no data available yet.
`dispatch_tcp` treats that result as peer closure while awaiting the body. A
separate Unix stream-pair control reproduces the same contrast.

This establishes a dependency framing defect that can reject a valid packet
delivered in segments. The logging-sensitive bootstrap results are consistent
with that defect; attributing every original bootstrap failure to it would
require a live capture. Debug success does not establish that normal transport
is fixed. Neither the shared gem nor the module's default payload is changed.

To reproduce the isolated contrast from the Framework root, use the current
locked payload source and the published probe. Exit 0 confirms this diagnostic

session context between RSpec examples, then also failed cleanup. Its **4/1/2**
plus one outside-example error is retained as a harness fault, with no owner
invocation. Restoring saved context before each example and after-all cleanup,
with fixture recovery in ensure, eliminates that error in both later frames.

both Docker contexts are empty, including stopped containers. Earlier command
and check qualifications remain current. Normal staged-PHP bootstrap, actual
default owning sessions, other payload families/releases and complete settings
recovery remain open. No new normal session or fully passing owner profile is
claimed. The complete valuable/container-feasible inventory goal remains active.

native execution. No PR is created.
