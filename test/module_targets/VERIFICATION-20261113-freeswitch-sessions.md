## Concerns

Initial native sessions work but their teardown verifier incorrectly requires
disappearance of genuine defunct FreeSWITCH API launcher children. The first
correction also misses a launcher that becomes defunct only after session close.
The target also lacks an external `kill`; the known telnet feeder now uses core
Perl after identity verification.
Complete failed runs are sealed before each fixture correction. The resulting
predicate requires the verified engine parent, UID, name, state, empty command,
absent executable and no sockets, with a per-command bound. Actual live children,
payload zombies and socket owners still fail. These provider leftovers are
recorded until container teardown; a pristine target process table is not claimed.

The first complete 14-case matrix passes three cases and fails eleven. Three
fail at a UTF-8/binary wire comparison; four x86 cases complete sessions but fail
because the observer watches the remote service port rather than Framework's
local HTTP port. Both verifier errors are corrected without changing the shared
capture helper. Its HTTP-only view names the actual target as initiator and
Framework as server; owning runtime endpoints remain unchanged. Four x64 native
generation failures then receive independent real-owner reproduction, establishing
the separate source defect before delegation. No architecture or original case
is removed. An exploratory unit default-datastore assumption is corrected before
the authoritative identical before/after suite.

Windows targets, other FreeSWITCH builds and other payload families remain
unqualified by this Linux lab. The separate credential-library concurrency race
remains deferred; this repair does not serialize scanners or mask that failure.
