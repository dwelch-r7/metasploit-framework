# Docker daemon finite execution

The three-case profile passed. Four real executions (two per declared target) produced exact UTF-8 root-owned bytes and their processes exited without a session. The normal Framework cleanup guard must reject a payload that cannot create a cleanup-capable session. Separate cases explicitly select `AllowNoCleanup=true`, then run genuine Linux and Python finite payloads twice through the owner and normal Debian cron. Native reads must prove exact UTF-8 marker bytes, root identity and process exit with no session or handler left.

The explicit opt-in permits residual cron and payload files. Tests record these files before controlled operator cleanup and do not claim that the owner automatically cleans them up. Only paths proven by a successful source container-create response are eligible for that cleanup.

```sh
DOCKER_CONTEXT=default BUILDX_BUILDER=default bundle exec ruby tools/dev/run_guarded_module_target_tests.rb docker_daemon_finite
```

See [the daemon profile](../docker_daemon/README.md) for shared setup and resource bounds.
