# openDCIM Linux dropper sessions

```sh
MODULE_TARGET_NAMESPACE=my-dcim-dropper bundle exec ruby tools/dev/run_guarded_module_target_tests.rb opendcim_dropper_x64 opendcim_dropper_x64_bourne opendcim_dropper_x86 opendcim_dropper_x86_bourne
```

These opt-in profiles extend the pinned official openDCIM **24.01**, MariaDB
**10.11.9** and 128 MiB reporting PostgreSQL [session fixture](../opendcim_sessions/README.md).
Only one three-service capped stack runs at a time; every phase removes its
containers and ephemeral resources before the next begins. Application source
stays unchanged, with Apache supplying `REMOTE_USER=dcim`.

| Profile | Architecture | Delivery |
| --- | --- | --- |
| `opendcim_dropper_x64` | x64 | Default-selected printf, then explicit printf |
| `opendcim_dropper_x64_bourne` | x64 | Bourne/base64 |
| `opendcim_dropper_x86` | x86 | Default-selected printf, then explicit printf |
| `opendcim_dropper_x86_bourne` | x86 | Bourne/base64 |

Each profile has three examples: real SQL/Graphviz/command and callback readiness,
an independently generated and launched stock native ELF Meterpreter session,
and two actual target-1 sessions. Native architecture or session failure withholds
the corresponding module verdict. The independent handler's already generated
ELF passes through the real printf or Bourne stager, executed as UID 33. Its
script checksum and exact dropped executable bytes are checked; ELF class/machine
fields must match the selected architecture. Normal native stager cleanup is
verified after session shutdown.

The owner first runs with AutoCheck, then repeats on the same selection with
AutoCheck disabled. The x64 case observes automatic payload selection; x86 is
selected explicitly. The normal `MeterpreterTryToFork=false` and HttpClient
timeout remain in effect. A fresh UID-33 directory is supplied through
`CMDSTAGER::TEMP` so every created file can be attributed and observed.

Passive traces retain the actual executable and command-stager returns. The
physical dropped executable must match the generated bytes and UID. Bourne's
base64 file is checked too. Commands that reach `poison_dot` must match every
generated stager command byte-for-byte, including the module's appended comment.
Each session performs public Meterpreter file/PID/identity operations and a fresh
response before remote shutdown. PID/birth disappearance, closed callback
connections, original SQL session-row closure and empty Framework jobs/sessions
are required.

The ordinary foreground stager removes its files after the payload exits.
Physical absence and an empty delivery directory are checked before any fixture
removal; the fixture then removes only its empty directory. All 145 configuration
rows, seeded LDAP settings, table registry and source fingerprints preserve,
with factory settings restored at the end.

These profiles do not establish default fetch readiness, HTTP authentication,
other releases or patched behavior. Ordinary unit CI excludes these Docker
profiles. A manifest registration alone does not prove qualification.
