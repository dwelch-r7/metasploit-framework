# Redis explicit encoder and custom-name qualification

The new [options profile](redis_replication_options/README.md) passes **2/0/0**
on the pinned genuine Redis 5.0.14 x64/Alpine target. It proves actual `x64/xor`
decoding, custom init/trigger names and a spaced Unicode library filename through
real owning sessions. No production source change is needed.

## Independent prerequisites and actual encoding

The profile extends the existing compiled SDK target and its writable tmpfs.
Native C compiler/loader/file controls run first. A stock handler selects
`x64/xor` before its generated bytes are embedded by the genuine SDK template.
That native session must be used and closed, with physical UID/PID/birth/file/
fresh-response/shutdown proof, before owning execution.

An independent Redis CLI round trip copies a real library to
`/data/module target é.so`, sets and reads that exact persistence filename,
loads/unloads the library and restores the original configuration and file set.
This establishes target support for the filename before the module handles it.

For each native and owning session, the test reads the actual encoder object
from the associated exploit. It requires `x64/xor`, its self-writing decoder
instruction, an encoded-buffer hash and an exact match between those encoded
bytes and the generated C declaration. The same session ID then receives the
public and independent physical proofs. Passing an ENCODER option or observing
an opened-session message alone cannot satisfy these assertions.

Two owning runs retain the default names while selecting the explicit encoder.
Two more also set `RedisModuleInit=mcv_named_1`,
`RedisModuleTrigger=mcv.named_1` and `RedisModuleName=module target é.so`.
The actual runtime names are checked. Each pair reuses the selected console
module on its second invocation. Four distinct callback ports, 4450/4451 and
4460/4461, and distinct encoded hashes guard against a stale compiled payload
satisfying a repeat. Real callback logs confirm those ports.

Every owning session is used and closed before comparing selected Redis state.
Both pairs restore the baseline after each run; jobs and session registrations
are empty, and generated native/owning C/shared-library hashes are retained.
