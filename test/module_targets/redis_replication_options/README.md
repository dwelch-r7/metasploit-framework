# Redis encoded payload and custom-name qualification

Run from the repository root:

```sh
MODULE_TARGET_NAMESPACE=my-redis-options-lab bundle exec ruby tools/dev/run_guarded_module_target_tests.rb redis_replication_options
```

This profile extends the pinned x64/Alpine compiled SDK lab. A real stock handler
selects `x64/xor` before its generated bytes are embedded by the SDK. The actual
encoder object, self-writing decoder instruction, encoded SHA256 and matching
generated C bytes are observed for each native and owning session. Public APIs
and independent PID/birth/UID/file/shutdown checks still gate session success.

Two owning runs use the explicit encoder with other defaults; two further runs
also set the module init/trigger names and a spaced Unicode `.so` filename.
An independent native CONFIG/loader round trip validates that exact filename
before owning calls. Each pair reuses the selected console module on its second
run. Selected state must reset after every run, and all sessions/jobs close.
Each owning run uses a different callback port so a stale compiled payload
cannot silently satisfy a repeat.
This profile is unqualified until its functional receipt passes.

Only the capped target/Framework pair runs, with a task-owned writable SDK tmpfs.
Namespaces and immediate teardown cover failures too. Other encoders, native
x86, authentication, replicas, existing data and wider process ancestry remain
separate.
