## Two distinct normal cleanup boundaries

The real CFML source is physically read before command execution and compared
with the module-generated source plus the genuine writer's trailing LF. At
normal `AllowNoCleanup=false`, the unchanged FileDropper path removes that file
and its `__` temporary directory when the session arrives. Its original cleanup
registries become empty, and independent native reads prove absence before
fixture cleanup. This boundary passes for all six fresh owner sessions,
including the replayed Bash pair.

The Linux ELF and Base64 source are removed by the **normal Bourne command
sequence after payload shutdown**. They are not attributed to FileDropper.
After public Meterpreter shutdown, both physical files are absent and the
private staging directory is empty. The fixture never manually removes these
owner payload files. It removes only its now-empty directory, independently
verifying directory absence. Independent native-control executables and proof
files have their separately recorded fixture cleanup.

Every admitted session is the sole active Framework session and has exactly
one open original SQL row. Public session APIs write the exact physical proof
marker and return identity/PID. The independent Perl observer ties that PID and
birth identity to the sole established callback socket by inode. SQL owner,
payload and original row ID match session metadata. Public shutdown follows a
fresh response; normal Framework session/job cleanup follows remote exit.
Every original row gains `closed_at`, all new payload/launcher processes
disappear, active callback sockets are absent and the full process set returns
to baseline before the next attempt.
