# Node V8 debugger native-gated TCP/TLS sessions

Date: 2026-11-21. The new profile exercises the original
`exploit/multi/misc/nodejs_v8_debugger` against the actual Node 7.10.1 legacy
debugger. All six native/owning TCP and TLS shells are used and closed. The
profile remains **failing**, because refused-port checking raises to the console
instead of returning a reason-bearing CheckCode. No production source is changed.

## Reproduction and target

```sh
MODULE_TARGET_NAMESPACE=nodejs-local bundle exec ruby tools/dev/run_guarded_module_target_tests.rb nodejs_v8
```

The [profile recipe](nodejs_v8/README.md) retains the Compose definition, native
client, ordinary timer program, observations and tests alongside Framework.
The existing module documentation links to it. One official
`node:7.10.1-alpine` image is pinned at
`sha256:4954ce53247180e207772f936223b11d52a7e4ee712dfe73fe2a75e39f785067`,
config `4b72b56791f9a7b9a590774e1e31fea46e9805d18a51aeb9190092d5cc0ba5ee`.
The observed Node binary SHA256 is
`3e9e231f9f2eb4a33488f2510ffa4ee6b2c564b5fbdcd1e160bcd39bdf19b5c7`.

The linux/amd64 target runs as UID1000, with a read-only root and source mount,
writable disposable `/tmp`, 128 MiB RAM/swap, 0.5 CPU and 64 PIDs. Its debugger
is published on a random loopback port. The timer keeps an ordinary program's
event loop active; the real Node binary provides the debugger service. Idle REPL
timing remains a separate path. Health checks inspect the listening socket
without competing for the debugger connection. See
[Node's archived debugger documentation](https://nodejs.org/download/release/v7.10.1/docs/api/debugger.html).

## Independent prerequisites and original owner behavior

The Python stdlib client speaks to the real V8 debugger. It parses actual
Content-Length headers and JSON, verifies Node identity and UID1000, then proves
plain and quoted Unicode/CRLF file bytes physically. An invalid expression must
fail, and files/process identity must recover. A separate native callback
round trip proves the host route. These precede any owning invocation.

The debugger uses its original TCP protocol; TLS applies to the callback payload.
Stock `nodejs/shell_reverse_tcp` and `nodejs/shell_reverse_tcp_ssl` sources are
generated by the normal Framework handler, syntax-checked and executed natively.
Each must produce a verified, usable shell before the original debugger exploit
runs that family twice on one selected module. Four real original owning calls
use the unchanged target0. The source has no AutoCheck; no AutoCheck refusal or
automatic check-before-exploit behavior is claimed.

Passive source-bound traces record original exploit/check calls and exact
messages. All four owner message expressions equal the stock generated payload
bytes, with correct header byte lengths. Real session-open events, original
owner/payload metadata, physical UID1000 file proof, shell PID/birth and parent,
a fresh response before exit and final process/socket closure verify use.
Two repeated checks on one selection return `Appears` with the protocol-detection
reason and do not invoke the exploit. The foreign file preserves bytes, UID,
mode and hash; final program/process state matches its baseline.
