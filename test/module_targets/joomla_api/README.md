# Joomla webservice access checks

From the repository root:

```sh
bundle exec ruby tools/dev/run_module_target_tests.rb joomla_api
```

The [vendor advisory](https://developer.joomla.org/security-centre/894-20230201-core-improper-access-check-in-webservice-endpoints.html)
identifies Joomla 4.0.0–4.2.7 as affected and 4.2.8 as fixed. Reviewed official
[4.2.7 router source](https://github.com/joomla/joomla-cms/blob/4.2.7/libraries/src/Router/ApiRouter.php)
merges query values into route defaults; the
[4.2.8 router](https://github.com/joomla/joomla-cms/blob/4.2.8/libraries/src/Router/ApiRouter.php)
removes the query's public flag. The API application's routing/authentication
then uses that route setting. Runtime router hashes must match those reviewed
source bytes, not just an advertised version.

Digest-pinned official Joomla 4.2.7/4.2.8 PHP 8.1.16 Apache images provide genuine
application/runtime code. MariaDB 11.2.2 is pinned separately. Joomla 4.2 has no
CLI installer; this lab follows the supplied manual-installation configuration,
imports its original SQL through its database driver, and hashes artificial
users with its password API. No application handler or API response is replaced.
There are separate databases for root, subdirectory, fixed and metadata-hardened
profiles. The latter denies actual static version resources through Apache.

Core Basic API authentication is enabled to establish a positive control:
correct administrator requests work on both releases, while ordinary anonymous,
incorrect-password and valid limited-user API requests are refused. This control
distinguishes the fixed access check from a broken or disabled endpoint. The
module itself uses the unauthenticated public query path. Native PHP verifies
versions, exact users/groups/password validity, live configuration and source
identity. A separate Net::HTTP/REXML client verifies real endpoint data, filtered
empty lists, version resources and refusal policies before module assertions.
Joomla intentionally omits the site secret from this configuration API; actual
database credentials and the other supported settings are checked exactly.

Twelve cases cover release checks, unavailable version metadata, unrelated HTTP,
repeated users/configuration reads with exact raw loot, and actual API-plugin
disable/restore paths with useful partial results. Public test accounts are in
accounts.json; all exposed credentials are disposable fixtures. A canonical
virtual host makes generated JSON links identical across native/module requests.
Existing human Scenarios are preserved; none are generated by this suite.

Only random loopback ports are published; no Docker socket or host listener is
mounted. The [shared runner](../README.md) retains native responses, commands,
image identities, exact counts, input hashes and owned teardown. Registration
alone is not qualification. Other releases, languages, API authentication modes,
large/paginated user sets and Framework database credential persistence remain
unqualified. Native filtered empty-list captures are parser evidence, not a
separate empty-user installation.
