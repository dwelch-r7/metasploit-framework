# Laravel token default Perl sessions

```sh
MODULE_TARGET_NAMESPACE=laravel-token-perl-local bundle exec ruby tools/dev/run_guarded_module_target_tests.rb laravel_token_perl
```

This profile uses the genuine pinned Laravel 5.6.29 target and an explicit lab
APP_KEY. It independently calibrates the hardened Faker denial and three working
installed-class HTTP gadgets. A native UID-33 callback and a stock Perl handler
session then gate normal default target/payload selection and repeated owner
execution on the same selected console module. The legacy owner has no AutoCheck
wrapper; the command profile separately checks its check method.

Each used session must create exact physical proof bytes, expose the persistent
Perl interpreter PID/birth and socket, and own an open reporting row. The Perl
payload launches a child shell for each command, so the proof observes its parent
PID. Public shell APIs request transport EOF, which ends the persistent Perl
loop; an exit command would end only a temporary child. The legacy fallback loop
can create several callbacks before asynchronous registration is observed. The
test derives the expected callbacks from the actual emitted gadget attempts and
the independently calibrated working gadgets. It uses and proves every fresh
session before closing all of them. Checks then require complete process/socket
baseline restoration and closure of every original reporting row.

The profile reuses the read-only four-worker Apache configuration and PHP process/
callback observers from the other session fixtures. It changes no vendor source
or payload implementation. Before/after source hashes, healthy HTTP and cgroup
events bracket the run. A capped application (1 CPU, 512 MiB/equal swap, 128 PIDs)
and reporting database (0.2 CPU, 128 MiB/equal swap, 64 PIDs) run serially with
other profiles. Published ports bind only to loopback.

Use the guarded runner with an explicit task namespace. Ensure cleanup removes
both containers, reporting data and the ephemeral network after success, failure
or interruption. Never leave a finished stack running. Failed native readiness
withholds the owner verdict. Other releases and patched packages require their
own native controls; these tests do not supply human Scenarios.
